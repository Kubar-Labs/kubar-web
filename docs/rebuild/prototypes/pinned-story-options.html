Two ways to pin the story

Scroll inside each screen. Both run the same eight steps with the site’s own copy. Option A pins the drawing and one panel together, and shows the static ledger when they don’t fit. Option B pins only the drawing, and each step’s words scroll past it as a card.

Where each one pins

Pick a row to load that screen below. Heights are the visible browser area, after the browser’s own bars.

A

One pinned panel

  • The drawing and the words for the current step stay still together; nothing moves past the reader.
  • Pins only when the drawing and the longest step both fit under the header. Everywhere else readers get the static ledger.
  • How it works step 06 runs to about 70 words, so that rail pins only on tall desktop screens.
B

Pinned drawing, scrolling text

  • Only the drawing has to fit, so it pins on every laptop and phone listed here.
  • Each step arrives as a card and the current one is raised. Long steps take longer to scroll past; no copy needs cutting.
  • The words move rather than stay put, and the story takes a little more scrolling.

How the fit is worked out. A uses rows of 64 px on laptops and 24 px on phones, as Claude Code proposed, and pins only if the drawing and the tallest step fit below the header. B sizes its rows from the screen: 44 to 74 px on laptops, and 22 to 40 px on phones with the drawing taking at most 45% of the screen; it pins down to about 545 px of height. The step text is the copy deck’s; the How it works panel keeps its three-line legend, as it does today.
